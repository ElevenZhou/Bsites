# 03 · 项目计划与里程碑

> 版本：v0.1（草稿）　|　关联：[01 PRD](./01-需求文档PRD.md)、[02 架构](./02-系统架构设计.md)、[07 协作](./07-团队协作与任务边界.md)
> 原则：**先验证质量，再谈规模。** 1→3→10→100 渐进放量，每个阶段有明确的"准入 / 准出"门槛。

---

## 1. 总体路线图

```
阶段0 立项与合规       阶段1 单账号MVP       阶段2 小矩阵(3~10)     阶段3 规模化(→100)     阶段4 运营优化
 调研/PRD/合规评审  →   端到端跑通1账号    →   多账号/防关联/熔断  →   产能/调度/批量    →   数据驱动/降本
   [当前]                  质量验证               稳定性验证             规模验证             持续迭代
```

> 时间不写死具体日期（取决于团队规模与合规结论）。下表为**相对周期估算**，立项会上据实际人力校准。

| 阶段 | 目标 | 估算周期 | 准出门槛（Exit Criteria） |
|------|------|----------|--------------------------|
| 0 立项与合规 | 拍板范围、合规口径、资源 | 1～2 周 | PRD/架构评审通过；⚠️合规结论明确；资源到位 |
| 1 单账号 MVP | 1 个账号端到端闭环 | 3～5 周 | 满足 [01 §6](./01-需求文档PRD.md) MVP 验收 |
| 2 小矩阵 | 3～10 账号稳定运行 | 4～6 周 | 防关联 / 熔断 / 监控可用；过审率达标；无重大风控事件 |
| 3 规模化 | 平滑扩到 100 | 6～10 周 | 100 账号可调度；自动化率达标；风控事件趋零且可恢复 |
| 4 优化 | 数据驱动、降本增效 | 持续 | 单条成本下降、效果提升、运营负担下降 |

## 2. 各阶段详情

### 阶段 0 · 立项与合规（前置，不可跳过）
- 评审 [01 PRD](./01-需求文档PRD.md)、[02 架构](./02-系统架构设计.md)。
- ⚠️ **合规评审（关键路径）**：平台规则、法律、许可证（`bilibili-api` 商用问题）、账号 / 实名 / 代理资源合规获取口径 → 输出 [05](./05-合规与风险管理.md) 结论。
- 确定首批垂类（建议 1～2 个低风险垂类先行）与内容形式。
- 资源就位：开发 / 运营人力、模型 API / 算力预算、首批账号与环境。
- **决策点 ✋**：合规不过则项目暂停或调整范围。

### 阶段 1 · 单账号 MVP（验证"质量能不能做出来"）
里程碑：
- M1.1 基础设施：项目脚手架、DB、队列、配置中心、日志。
- M1.2 账号服务 + 登录态 + 投稿（biliup 封装）→ **能手动发一条成功**。
- M1.3 内容流水线：文案→TTS→字幕→合成→封面 → **能自动产一条成片**。
- M1.4 审核：自动预审 + 人工审核台。
- M1.5 端到端串联 + 排期 + 数据回收 + 告警。
- M1.6 跑 2～4 周真实内容，观察过审率与平台反馈。
- **准出**：满足 MVP 验收清单；内容质量获运营认可。

### 阶段 2 · 小矩阵（验证"多账号稳不稳")
- M2.1 ⚠️ 防关联环境层：指纹 profile 池 + 代理 IP 池 + 账号绑定。
- M2.2 账号分片调度 + 拟人化发布（错峰 / 抖动）。
- M2.3 风控熔断 + 健康度看板。
- M2.4 跨账号选题去重、内容差异化。
- M2.5 3→10 账号灰度，监控关联 / 限流信号。
- **准出**：多账号稳定、无重大风控、监控告警可用。

### 阶段 3 · 规模化（验证"能不能撑到 100")
- M3.1 产能扩容（worker 池、模型并发、成本控制）。
- M3.2 批量运营工具（分组配置 / 排期 / 操作）。
- M3.3 环境资源池规模化与运维自动化。
- M3.4 10→30→60→100 分批放量，每批观察后再加量。
- **准出**：100 账号可调度运行；自动化率与过审率达标；风控可控可恢复。

### 阶段 4 · 运营优化（持续）
- 数据驱动选题 / 标题 / 封面 / 时段 A/B。
- 降本：模型选型、本地化、缓存复用。
- 内容质量与垂类专业度持续打磨。

---

## 3. 关键依赖与关键路径

- ⚠️ **合规结论**（阶段 0）是整条路径的前置闸门，阻塞则全盘阻塞。
- **投稿稳定性**（biliup + 登录态）是阶段 1 的核心技术风险。
- **防关联环境**（阶段 2）是规模化的前置条件。
- **资源供给**（账号 / 实名 / 代理 / 算力）由运营 / 行政侧并行准备，避免卡开发。

## 5. 风险登记册（Risk Register，摘要，详见 [05](./05-合规与风险管理.md)）

| 风险 | 等级 | 应对 |
|------|------|------|
| ⚠️ 批量账号违反平台规则被封 | 高 | 渐进放量、合规优先、熔断、单账号隔离 |
| ⚠️ 内容低质重复被限流 | 高 | 原创度校验、内容差异化、人工审核 |
| ⚠️ 许可证 / 商用合规（GPL） | 中高 | 选型评审、替代方案、法务确认 |
| 账号关联导致连锅 | 中高 | 设备 / 网络 / 行为隔离 |
| 登录态频繁失效 | 中 | 监控、刷新、告警 |
| AI 成本超预算 | 中 | 模型分级、本地化、缓存 |
| 内容方向不被受众认可 | 中 | 小步快跑、数据反哺 |
