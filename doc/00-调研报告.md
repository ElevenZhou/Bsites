# 00 · 调研报告

> 目的：在动手前摸清"轮子"。回答两个问题——**有没有可直接用 / 可学习的同类项目？** **每一类能力（采集、加工、生成、分发、矩阵管理、防风控）的成熟方案是什么？**
> 时间：2026-06。结论会随平台规则与项目迭代变化，请定期复核。

---

## 0. 总体结论（TL;DR）

1. **不存在一个开箱即用、专为"B站 100 账号 AI 自动运营"打造的成熟开源产品。** 但每个环节都有可复用的成熟轮子，工程上是"集成 + 编排"而非"从零造"。
2. 最值得直接复用的轮子：
   - **投稿上传**：`biliup` / `biliup-rs`（B站投稿事实标准）。
   - **B站综合 API**：`bilibili-api`（Nemo2011，登录态、数据、动态等）。
   - **多平台分发**：`social-auto-upload (SAU)`（含 B站、抖音、小红书、视频号）、`MultiPost`（浏览器扩展）。
   - **AI 短视频生成**：`MoneyPrinterTurbo`（关键词→成片，"智能缝合"素材，规避版权）。
   - **数据采集**：`MediaCrawler`（多平台公开数据采集，用于选题 / 竞品分析）。
   - **AI 子能力**：TTS（edge-tts / CosyVoice / GPT-SoVITS）、字幕（Whisper / faster-whisper）、口型 / 数字人（Heygem / Wav2Lip / MuseTalk / SadTalker）。
3. ⚠️ **最大的不确定性不在技术，而在合规与风控**：批量账号、自动化投稿、素材"缝合 / 搬运"都触碰 B站社区规则与版权红线。100 账号规模化前，必须先解决防关联、内容原创度、限流 / 封号的风险（见 [05 合规与风险管理](./05-合规与风险管理.md)）。这是项目能否成立的前提，而非附加项。

## 1. 多账号 / 矩阵管理 + 自动投稿

| 项目 | 开源 | 地址 | 核心能力 | 备注 |
|------|------|------|----------|------|
| **biliup** | ✅ | github.com/biliup/biliup | 自动直播录制、**B站投稿**、频道搬运；Web 界面 + 多种登录方式 + 多 P 投稿；Rust 核心 + Python 包 + SQLite | 投稿环节首选，可作库嵌入（`biliup.plugins.bili_webup`） |
| **biliup-rs** | ✅ | github.com/biliup/biliup-rs | 命令行投稿 / 下载，多登录方式，多 P，可手动切线路 | 适合脚本化批量投稿 |
| **social-auto-upload (SAU)** | ✅ | github.com/dreammis/social-auto-upload | 一键自动上传到抖音 / 小红书 / **B站** / 视频号 / TikTok，支持定时发布、多账号 | 矩阵分发最贴合需求的开源脚本 |
| **MultiPost** | ✅ | multipost.app | 浏览器扩展，一键多平台发布图文 / 视频，自动适配各平台规则，无需 API key | 适合半自动、人工在环节点 |

> 国际同类（Postiz / Mixpost / social-publish）走官方 OAuth、**不支持国内平台**，仅作架构与调度设计参考，不能直接用于 B站。

**可借鉴点**：SAU 的"账号配置 + 定时任务 + 浏览器自动化登录态"模型，可直接作为我们矩阵调度层的设计蓝本。biliup 的"库化投稿"让我们能把上传封装成内部服务。

## 3. AI 内容生产（文案 / 视频 / 配音 / 字幕 / 数字人）

### 3.1 一站式生成
- **MoneyPrinterTurbo**（harry0703，★23k+）：输入主题 / 关键词→自动文案、素材采集（Pexels/Pixabay）、字幕、配乐、合成；"智能缝合"现成素材规避版权；支持 GPT / 通义 / 文心 / Ollama 等 + Edge/Azure/百度 TTS；MVC 架构、Web + API、批量生成。v1.2.8（2026-05）接入 LiteLLM（100+ 模型网关）。**侧重"生成"，发布仍需自行对接**——正好与我们的分发层互补。

### 3.2 可自由组合的子能力（纯开源流水线）
| 环节 | 候选 |
|------|------|
| 文案 / 选题 | 大模型 API（Claude / 通义 / GLM 等）+ 自定义 prompt |
| TTS 配音 | `edge-tts`（免费）、`CosyVoice`、`GPT-SoVITS`（声音克隆）、`ChatTTS` |
| 字幕 / 转写 | `Whisper` / `faster-whisper` |
| 口型 / 数字人 | `Heygem`（离线、克隆形象+声音，前端开源）、`Wav2Lip`、`MuseTalk`、`SadTalker` |
| 剪辑合成 | `ffmpeg`、`MoviePy`、剪映导出协议（半自动） |

### 3.3 商业一站式（备选，省事但有成本 / 合规约束）
腾讯智影、闪剪、秒创、讯飞智作、A2E（含 API）。适合人力不足时外包部分口播 / 数字人产能。

**可借鉴点**：以 MoneyPrinterTurbo 的流水线为"成片生成"模块原型；数字人 / 口播作为部分垂类（知识、资讯播报）的高效产能；其余垂类以"素材二创 + 文案 + 配音 + 字幕"组合。

## 4. 矩阵 / 养号 / 防关联（⚠️ 风控核心）

平台关联检测普遍是**四层模型**：行为层（发布时间 / 操作习惯 / 内容风格一致性）、网络层（IP / DNS / 网络指纹）、设备层（设备指纹 / 浏览器指纹 / 硬件特征）、账号层（手机号 / 实名 / 登录设备绑定）。

- **浏览器指纹极难隐藏**：Canvas、WebGL、字体、分辨率、系统版本、插件、时区 / 语言组合成"数字身份证"；清 cookie 无效；WebRTC 还会泄露真实内网 IP（即使用代理）。
- **常见防关联手段**：指纹浏览器（AdsPower / 云登 / 比特 等）为每账号虚拟一套"准真实设备"环境；配独立住宅代理 IP；不同手机号 / 邮箱注册；首登"养号"（刷推荐、真实互动、完善资料）；操作随机化、控制频率。
- **五大原则**：设备隔离、网络隔离、账号差异化、内容多样化、操作随机化。

⚠️ **风险与事实**：
- 上述方法多来自**指纹浏览器厂商的营销内容**，"保证不封"不可信。
- 真实翻车案例：32 个账号同时运营因共享密码被盗号、三个月粉丝一夜清零；某 MCN 用一套脚本生成 200 条视频被判"低质重复"限流。
- 接码注册、批量自动化、内容重复都可能**违反平台 ToS 乃至相关法律法规**；B站官方"营销号"细则需直接查其《社区公约》/ 创作规则（搜索结果覆盖不足，须人工核实）。

**结论**：防关联是规模化的必要工程，但"零封号"不存在。策略应是 **合规优先 + 渐进放量 + 异常熔断**，而非"对抗到底"。详见 [05](./05-合规与风险管理.md)、[04](./04-账号运营与养号策略.md)。

## 5. 数据采集（选题 / 竞品 / 效果分析）

- **MediaCrawler**：多平台公开数据采集（小红书 / 抖音 / 快手 / B站 / 微博 / 贴吧 / 知乎），用于热点选题、竞品拆解、标签 / 封面研究。⚠️ 仅采集**公开**数据，注意频率与 robots / ToS。

## 6. 对本业务的可借鉴点与风险提示

**可借鉴 / 可复用**
1. 采集→生成→分发分三层，每层都有现成轮子，工程重心在**编排、配置化、账号态管理、监控**。
2. 投稿用 biliup（库化）；分发调度参考 SAU；生成参考 MoneyPrinterTurbo；数据用 MediaCrawler + bilibili-api。
3. 设计"人工在环"卡点：审核、风控异常、敏感垂类，由半自动兜底。

**风险提示（务必同步给决策层）**
1. ⚠️ **合规是项目成败的前置变量**，不是后置补丁。100 账号批量自动化在 B站属高风险操作，需法务 / 平台规则评审。
2. ⚠️ **许可证**：`bilibili-api` GPL v3 且声明勿商用；多数开源工具仅供学习测试。商用须做许可证合规审查。
3. ⚠️ **内容原创度 / 版权**：素材"缝合 / 搬运"易触发低质重复限流与版权投诉；需建立原创度与查重机制。
4. ⚠️ **防关联无银弹**：指纹浏览器 + 代理是降险不是免责；规模越大暴露面越大。
5. **建议路线**：先做 **1～3 个账号的端到端 MVP**，验证内容质量、过审率、风控反馈，再决定是否放量到 100。
