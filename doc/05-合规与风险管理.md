# 05 · 合规与风险管理 ⚠️

> 版本：v0.1（草稿）　|　**全员必读**　|　关联：[00 调研](./00-调研报告.md)、[01 PRD](./01-需求文档PRD.md)、[03 计划](./03-项目计划与里程碑.md)
>
> **本文档的立场**：合规不是项目的"附加项"，而是**前置闸门**。100 个账号 + 自动化 + 内容生产，天然处在平台规则与法律的敏感地带。本文档的目的是让团队**清醒地认识风险、主动降险、守住底线**，而不是教如何对抗平台。

---

## 0. 红线（不可逾越）

以下行为**一律不做**，无论是否被发现：

- ❌ 刷播放、刷粉、刷点赞 / 评论等虚假数据；买量。
- ❌ 盗号、撞库、利用他人身份 / 实名信息注册账号。
- ❌ 破解、攻击、绕过平台付费 / 风控的技术手段。
- ❌ 发布违法违规、虚假、侵权、低俗、误导性内容。
- ❌ 未经授权搬运 / 抄袭他人作品。
- ❌ 伪造资质、冒充官方 / 他人。

> 任何功能设计若依赖以上行为才能成立，应**直接否决该设计**，而非寻找规避手段。

## 1. 主要风险分类

### 1.1 平台规则风险（B站 ToS / 社区规则）
- 批量账号、矩阵化运营、自动化投稿可能违反 B站用户协议与社区公约。
- "营销号 / 低质重复 / 搬运号"是平台重点打击对象。
- ⚠️ **行动项**：项目立项阶段，**指定专人通读并摘录 B站现行《用户协议》《社区公约》《创作激励 / 创作规范》《自媒体 / 矩阵相关规则》**，形成内部口径附在本文档附录。规则会变，需定期复核。

### 1.2 账号关联与封号风险
- 平台四层关联检测（行为 / 网络 / 设备 / 账号），同环境多账号易被连锅封禁。
- 真实案例：共享密码致批量盗号清零；一套脚本量产 200 视频被判低质限流。
- 防关联手段（指纹浏览器 / 代理）**只能降险，厂商"保证不封"不可信**。

### 1.3 内容版权风险
- 素材"缝合 / 搬运"、影视游戏二创涉及版权与合理使用边界。
- 可能引发版权投诉、下架、账号处罚乃至法律纠纷。

### 1.4 法律与数据合规风险
- 实名 / 手机号 / 个人信息的获取与存储须合法合规（个人信息保护）。
- 接码注册、虚拟身份可能涉及违规。
- 采集公开数据须遵守频率、robots、平台 ToS，不碰非公开 / 个人隐私数据。

### 1.5 知识产权 / 许可证风险
- ⚠️ `bilibili-api` 为 **GPL v3**，作者声明"仅供学习测试、勿商用 / 勿违规"。
- 多数开源工具（biliup 等）有各自许可证，商用前须逐一审查。
- GPL 传染性可能影响闭源后端架构。

### 1.6 商业与运营风险
- AI 内容成本不可控；内容方向不被受众认可；规模化后管理失控。

## 3. 降险策略（贯穿系统设计）

1. **合规优先于功能**：任何特性以不违反规则 / 法律为前提。
2. **渐进放量**：1→3→10→100，每批观察平台反馈再加量（见 [03](./03-项目计划与里程碑.md)）。
3. **质量优先**：原创度校验 + 人工审核 + 内容差异化，远离"低质重复"判定。
4. **账号隔离**：每账号独立环境，故障隔离，防连锅。
5. **熔断机制**：异常即暂停 + 告警 + 人工排查（见 [04 §7](./04-账号运营与养号策略.md)）。
6. **人工在环**：判断与把关交给人，自动化只做产能。
7. **数据最小化 + 加密**：登录态 / 实名 / 代理凭据加密、最小权限、可审计。
8. **可追溯**：全链路日志审计，出事能复盘。

### 3.5 防关联与隔离强度（指纹浏览器 / IP 代理）⚠️

**结论：不是"必须",而是"按操作环节 × 运营阶段分级"。** 一上来给 100 个账号每号配指纹浏览器 + 住宅 IP 通常是过度投入；完全不隔离规模化后又会连锅。

**先按操作环节判断需求**（B站投稿走 cookie/API，非浏览器）：
| 操作 | 指纹浏览器依赖 | IP 隔离依赖 |
|------|----------------|-------------|
| 注册 / 登录 | 高 | 高 |
| 投稿上传（biliup） | **低** | 中 |
| 互动 / 养号 | 中 | 中 |

**防关联强度对照表**：
| 强度 | 配置 | 成本 | 适用阶段 | 主要风险 |
|------|------|------|----------|----------|
| 无隔离 | 单机单 IP、全部账号 | ≈0 | ❌ 不可用于矩阵 | 一关联全连锅 |
| 轻量 | 多 IP 分散 + 每号独立 cookie/登录态 + 行为错峰 | 低 | ✅ MVP / 小矩阵(1~10) | 设备指纹仍可能关联 |
| 中度 | 指纹浏览器(注册/养号) + 分组共享代理池 | 中 | ✅ 规模化(10~100) | 共享 IP 池被污染 |
| 重度 | 每号独立指纹 + 独立住宅 IP(+独立设备/手机) | 高(随账号线性增长) | 按预算/风控选用 | 成本失控；仍非"零封" |

**原则**：
- ⚠️ **隔离是降险不是免责**——厂商"保证不封"不可信；隔离强度高于内容质量是本末倒置（低质重复内容栽在内容，不是关联）。
- 优先级：内容原创度 / 拟人化节奏 / 渐进放量 / 熔断 **>** 隔离强度。
- ⚠️ **前置**：先定性本业务（见 §5 第 1 条）。若是合规团队/MCN 运营，隔离需求大幅降低；若是批量营销号，隔离只是在风险上加杠杆。
- 架构落地（资源池化、分阶段升级）见 [02 §7.5](./02-系统架构设计.md)；运营节奏见 [04 §5](./04-账号运营与养号策略.md)。

## 4. 合规检查清单（每阶段准出前自查）

**立项阶段**
- [ ] 已通读并摘录 B站现行平台规则，形成内部口径。
- [ ] 已确认账号 / 手机号 / 实名 / 代理资源的**合法获取**方式。
- [ ] 已完成开源依赖的**许可证审查**（尤其 GPL 商用问题）。
- [ ] 决策层已知悉 R1～R6 风险并接受 / 给出边界。

**MVP / 放量阶段**
- [ ] 内容发布前过自动预审 + 原创度校验。
- [ ] 敏感 / 中高风险内容有人工审核。
- [ ] 无任何红线行为（§0）。
- [ ] 熔断与告警可用并演练过。
- [ ] 登录态 / 个人信息加密存储、可审计。
- [ ] 二创 / 搬运类内容有版权来源与授权依据。

## 5. 待决合规问题（须决策层 / 法务拍板）

1. ⚠️ 本业务在 B站规则下的**定性**：是否属于被允许的"团队 / MCN 运营"，还是被禁止的"批量营销号"？边界在哪？
2. ⚠️ 账号、手机号、实名信息如何**合法**获取与持有？
3. ⚠️ `bilibili-api` 等 GPL / "勿商用"依赖的处理：替换、自研、还是法务确认可用？
4. ⚠️ 二创 / 素材搬运的版权口径与合理使用边界？
5. ⚠️ 是否需要法律意见书 / 外部合规咨询？

> 在上述问题有明确结论前，**项目不进入规模化（阶段 3）**。
