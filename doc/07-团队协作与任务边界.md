# 07 · 团队协作与任务边界

> 版本：v0.1（草稿）　|　关联：[01 PRD](./01-需求文档PRD.md)、[03 计划](./03-项目计划与里程碑.md)
> 目的：统一**角色、边界、协作流程、任务拆解**，让后续开发同事接手时不踩坑、不撞车。

---

## 1. 角色与职责（RACI 简版）

| 职责域 | 负责（R） | 配合（C） | 知会（I） |
|--------|-----------|-----------|-----------|
| 产品 / 需求 | 产品 | 运营、开发 | 全员 |
| 内容策略 / 选题 / 审核 | 运营 | 产品、AI | 开发 |
| 系统架构 / 开发 | 开发 | 架构 | 全员 |
| 账号 / 环境 / 资源 | 系统管理员 | 行政、运营 | 开发 |
| ⚠️ 合规 / 法务 | 合规负责人 | 法务、决策层 | 全员 |
| 监控 / 运维 | 运维 | 开发 | 运营 |
| 决策 / 预算 | 决策层 | 全员 | 全员 |

> 小团队可一人多角，但**每个职责域必须有明确 Owner**。⚠️ 合规域不可缺位。

## 2. 模块归属（开发任务边界）

> 对应 [02 架构](./02-系统架构设计.md) 的模块。每模块一个 Owner，接口先约定再并行开发。

| 模块 | Owner | 上游依赖 | 下游消费 | 对外接口（约定） |
|------|-------|----------|----------|------------------|
| 账号服务 | 待定 | 环境层 | 全部 | 账号 CRUD、登录态、健康度 API |
| 策略服务 | 待定 | — | 选题、加工 | 画像 / 策略 / 排期 读写 |
| 选题 Agent | 待定 | 策略、采集、LLM | 加工 | 选题生成 / 去重 |
| 采集 Worker | 待定 | 选题 | 加工 | 素材入库、版权标记 |
| 加工/合成 | 待定 | 采集、AI 能力 | 审核 | 成片产出 |
| 审核/风控 | 待定 | 加工 | 投稿 | 风险分、审核决策 |
| 投稿 Worker | 待定 | 审核、账号 | 数据回收 | 投稿、回执、重试 |
| 数据回收 | 待定 | 投稿、账号 | 策略 | 数据快照、分析 |
| 调度/队列 | 待定 | — | 全部 | 任务编排、限流 |
| 配置中心 | 待定 | — | 全部 | 配置读写 / 热更新 |
| 监控告警 | 待定 | 全部 | 运营/运维 | 指标、告警 |
| Web 后台 | 待定 | 各服务 API | 人 | 控制台 |
| ⚠️ 环境层 | 系统管理员 | 采购 | 账号服务 | profile / 代理分配 |

**接口先行原则**：模块间先定义 API 契约（输入 / 输出 / 状态），再各自并行实现，避免集成期返工。

## 3. 协作流程

### 3.1 文档驱动
- 一切从 `doc/` 出发：需求看 01，架构看 02，计划看 03。
- 文档是单一事实来源；口头约定须回写文档。
- 重大变更走"提议 → 评审 → 更新文档 + 变更记录"。

### 3.2 开发流程（建议）
- 分支：功能分支 → PR → Review → 合并 `main`。
- ⚠️ 涉及投稿 / 账号 / 合规敏感逻辑的 PR，需 Owner + 合规知会。
- 提交信息清晰；关键决策写入对应文档。

### 3.3 例会
- 周会：进度（对照 [03 里程碑表](./03-项目计划与里程碑.md)）、阻塞、风险。
- 阶段评审：每阶段准出前对照检查清单（含 [05 合规清单](./05-合规与风险管理.md)）。

## 5. 命名与约定

- 文档：`doc/两位编号-中文名.md`，新增同步更新 [doc/README.md](./README.md) 导航。
- 代码：英文命名；模块边界对齐 [02 架构](./02-系统架构设计.md)。
- 配置 / 密钥：⚠️ 不入库明文；登录态 / 代理 / 实名加密存储。
- 任务跟踪：本文档 Backlog 为草案，正式执行迁移到项目管理工具（飞书 / Issue），本文档保留链接。
