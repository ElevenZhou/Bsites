# 02 · 系统架构设计

> 版本：v0.1（草稿）　|　关联：[01 PRD](./01-需求文档PRD.md)、[06 技术选型](./06-技术选型与开源参考.md)
> 原则：**配置驱动、模块解耦、人工可在环、异常可熔断、全程可观测。**

---

## 1. 设计原则

1. **分层流水线**：采集 → 加工 → 合成 → 审核 → 投稿 → 回收，各阶段产出物落库，任一阶段可单独重跑。
2. **配置驱动**：账号画像、内容策略、排期、风控规则全部配置化，运营改配置而非改代码。
3. **人工在环（Human-in-the-loop）**：审核、风控异常、敏感垂类设卡点，自动流可降级为半自动。
4. **账号隔离**：每账号独立登录态 + 独立指纹 / 代理环境，互不串号（⚠️ 见 [05](./05-合规与风险管理.md)）。
5. **异常熔断**：检测到风控 / 限流 / 登录失效，自动暂停相关账号与任务并告警。
6. **可观测**：任务、账号、内容全链路日志 + 监控 + 告警。
7. **渐进放量**：架构支持从 1 个账号平滑扩到 100 个（无状态 worker + 队列 + 账号分片）。

## 3. 模块职责

| 模块 | 职责 | 关键依赖 | 对应 PRD |
|------|------|----------|----------|
| 管理后台 | 配置、审核、监控的人机界面 | Web 前端 | 全部 M-* |
| 账号服务 | 账号档案、登录态、环境绑定、健康度 | DB、环境层 | M-Account |
| 策略服务 | 画像、内容策略、排期规则 | DB | M-Strategy |
| 选题 Agent | LLM 生成选题、去重、入库 | LLM、向量库、采集 | M-Strategy |
| 采集 Worker | 按选题取素材、入库、版权标记 | 素材库 API、MediaCrawler | M-Source |
| 加工/合成 Worker | 文案 / TTS / 字幕 / 数字人 / 剪辑 / 封面 → 成片 | LLM、TTS、Whisper、ffmpeg、数字人 | M-Produce |
| 审核/风控服务 | 自动预审 + 人工审核台 + 风险路由 + 熔断 | 规则引擎、敏感词库 | M-Review |
| 投稿 Worker | 封装 biliup 投稿、排期、回执、重试 | biliup、账号登录态 | M-Publish |
| 数据回收 Worker | 拉取账号 / 内容数据，分析反哺 | bilibili-api 数据接口 | M-Analytics |
| 调度/队列 | 定时排期、任务分发、限流、重试 | Scheduler + MQ | M-System |
| 配置中心 | 统一配置读写、热更新 | DB / 配置存储 | M-System |
| 监控告警 | 指标、日志、告警通知 | 日志/监控栈、飞书/邮件 | M-System |
| 环境层 | 指纹 profile、代理 IP、登录态隔离 | 指纹浏览器、代理服务 | M-Account |

## 4. 核心数据模型（草案）

```
Account            账号
  id, nickname, vertical(垂类), persona(画像JSON), status,
  env_id(→Environment), credentials_ref(登录态加密引用),
  created_at, health(JSON)

Environment        防关联环境（⚠️）
  id, fingerprint_profile, proxy_ref, last_check_at, status

Strategy           内容策略
  id, account_id, form(口播/二创/数字人/图文), tone, frequency,
  publish_windows, taboo_words, ref_accounts

Topic              选题
  id, account_id, title, source(热点/AI/人工), status, embedding(查重)

Material           素材
  id, topic_id, source, license(授权), uri, meta(JSON), dedup_hash

Content            内容/稿件
  id, topic_id, account_id, script, audio_uri, subtitle_uri,
  video_uri, cover_uri, originality_score, status(草稿/待审/已审/已发/失败)

ReviewRecord       审核记录
  id, content_id, risk_score, auto_flags, reviewer, decision, note

PublishJob         投稿任务
  id, content_id, account_id, scheduled_at, status, bvid, fail_reason, retries

MetricSnapshot     数据快照
  id, content_id/account_id, ts, views, likes, comments, fans_delta, ...

AuditLog           审计
  id, actor, action, target, ts, detail
```

> 登录态 / 代理凭据**加密存储**，库中只存引用，不存明文。

## 5. 关键流程

### 5.1 端到端内容生产（自动 + 人工卡点）
```
排期触发 → 选题(取/生成) → 采集素材 → 文案 → 配音 → 字幕 → 合成成片 → 封面
   → 自动预审(风险分) → [低风险:直发 | 中高风险:人工审核台]
   → 投稿(biliup, 按账号环境+登录态) → 回执/重试 → 数据回收 → 反哺策略
```

### 5.2 风控熔断
```
数据回收/投稿回执检测异常(限流/异常播放骤降/投稿被拒/登录失效)
   → 标记账号状态 → 暂停该账号排期与在途任务 → 告警通知运营 → 进入人工排查 SOP
```

### 5.3 拟人化发布
- 每账号独立时段窗口 + 随机抖动；跨账号错峰；避免整点齐发；模拟真人操作节奏（见 [04](./04-账号运营与养号策略.md)）。

## 7. 扩展性：从 1 到 100

- **无状态 Worker + 队列**：产能不足时横向加 worker。
- **账号分片**：按账号 / 垂类分片调度，互不影响；单账号故障隔离。
- **环境池化**：指纹 profile 与代理 IP 作为可分配资源池，账号动态绑定。
- **配置化垂类模板**：新增垂类 = 加一份策略模板 + 素材源配置，不改代码。
- **限流与配额**：全局与单账号双层限流，防止"齐步走"触发风控。

## 7.5 环境层：防关联与隔离分级（⚠️）

> 多账号是否需要指纹浏览器 + IP 代理？**不是非黑即白，按"操作环节 × 运营阶段"分级。** 详细强度对照与合规前提见 [05 §3.5](./05-合规与风险管理.md)；本节给架构落地。

### 7.5.1 按操作环节区分需求
| 操作 | 技术形态 | 指纹浏览器依赖 | IP 隔离依赖 |
|------|----------|----------------|-------------|
| 注册 / 登录 | 浏览器 / App | 高（登录态绑定最敏感） | 高 |
| **投稿上传** | biliup 走 **cookie/API**，非浏览器 | **低** | 中（同一 IP 批量投稿是明显信号） |
| 互动 / 养号 | 浏览器 / App | 中 | 中 |

> 关键：B站投稿主要是 cookie+API 路径，**指纹浏览器的价值集中在注册与养号互动**；纯投稿环节优先保证 **IP 不要 100 个账号全从一台机器出去**。

### 7.5.2 隔离强度分级（架构按"资源池"实现）
```
无隔离 ── 轻量隔离 ── 中度隔离 ── 重度隔离
单机单IP   多IP+独立     指纹浏览器    每号独立指纹+
全部账号   cookie隔离    +分组代理     独立住宅IP(+独立设备)
成本≈0     低            中           高(随账号数线性增长)
```
- **环境层把"指纹 profile + 代理 IP"作为可分配资源池**，账号按当前阶段动态绑定不同强度的环境（`Environment.status` / 强度等级字段）。
- 升级隔离强度 = 给账号重新分配更高等级的环境，**不改业务代码**。
- 代理可分组共享（中度）或一号一住宅 IP（重度），按预算与风控反馈切换。

### 7.5.3 分阶段落地建议（对齐 [03 计划](./03-项目计划与里程碑.md)）
- **阶段1 MVP / 阶段2 小矩阵(1~10 号)**：**轻量隔离**即可——IP 适度分散 + 每号独立 cookie/登录态 + 行为错峰；资源压在内容质量与过审率上，**暂不上指纹浏览器**。
- **阶段3 规模化(放量至 100)**：引入**指纹浏览器(注册/养号)+ 代理 IP 池(投稿/互动)**，作为资源池运维；是否"每号独立住宅 IP"按预算与风控反馈决定，可分组共享。
- ⚠️ **隔离是降险不是免责**：再强的指纹也救不了低质重复内容（调研中"一套脚本量产 200 视频被判低质限流"栽在内容而非关联）。内容原创度、拟人化节奏、渐进放量、异常熔断的优先级**高于**隔离强度。

---

## 8. 安全与合规要点（架构侧）
- ⚠️ 登录态 / 代理 / 实名信息加密、最小权限、可审计。
- ⚠️ 内容发布前过审 + 原创度校验，留痕。
- ⚠️ 熔断与人工兜底是默认能力，不是可选项。
