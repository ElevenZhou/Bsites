## 1. 背景与目标

### 1.1 背景
B站内容生态成熟、垂直领域众多。以单人单号方式运营难以规模化产出。我们希望借助 AI 与自动化，**以接近真人的运营质量**，同时经营约 **100 个**分布在不同垂直领域的 B站账号，使其成长为各领域优秀、专业的 UP 主。

### 1.2 业务目标（North Star）
> 用尽可能少的人力，稳定产出**过审、不被限流、有真实受众价值**的内容，让 100 个账号在各自垂类持续涨粉并建立专业形象。

### 1.3 可量化目标（建议，待运营确认）
| 维度 | MVP（阶段一） | 规模化（阶段三） |
|------|--------------|------------------|
| 账号数 | 1～3 | 100 |
| 单账号更新频率 | 可配置（如 2～4 条/周） | 同上，按垂类差异化 |
| 内容过审率 | ≥ 95% | ≥ 98% |
| 自动化率（无需人工） | ≥ 50% | ≥ 80% |
| 严重风控事件（封号/大限流） | 0 | 趋近 0，且有熔断与恢复 SOP |
| 单条内容人工耗时 | 基线测量 | 较基线下降 ≥ 70% |

> ⚠️ 以上为内部效率目标，**非"刷量"目标**。不设虚假互动 / 买量类指标。

### 1.4 非目标（Out of Scope，至少一期不做）
- 不做刷播放 / 刷粉 / 刷互动等虚假数据。
- 不做绕过付费 / 破解 / 攻击平台。
- 一期不覆盖直播自动化、商业广告投放、电商带货闭环。
- 不承诺"绝对不封号"——风控只能降险，不能消除。

## 2. 用户与角色

| 角色 | 描述 | 关心什么 |
|------|------|----------|
| 运营负责人 | 制定垂类策略、账号画像、内容方向 | 账号成长、过审率、风控 |
| 内容运营 | 维护选题库、审核稿件、处理人工卡点 | 效率、质量、审核工具好不好用 |
| 系统管理员 | 维护账号池、代理 / 指纹环境、调度 | 稳定性、监控告警、账号健康度 |
| 开发 / 运维 | 建设与维护系统 | 架构清晰、可观测、可扩展 |
| 决策层 | 投入产出、合规风险 | ROI、法律 / 平台风险 |

## 4. 功能需求（按模块）

> 标注：`[P0]` MVP 必须 ／ `[P1]` 规模化需要 ／ `[P2]` 增强项。每条尽量可验收。

### 4.1 账号与矩阵管理（M-Account）
- `[P0]` 账号档案：昵称、垂类、画像 / 人设、登录态（cookie/token）、绑定的代理 / 指纹环境、状态（正常/养号中/限流/封禁/停用）。
- `[P0]` 账号分组与标签（按垂类、按阶段）。
- `[P0]` 登录态管理：安全存储、过期检测与刷新提醒、失效告警。
- `[P1]` 账号健康度看板：近 N 日发布、过审、播放 / 涨粉、风控事件。
- `[P1]` ⚠️ 防关联环境绑定：每账号一套指纹浏览器 profile + 独立代理 IP（见 [05](./05-合规与风险管理.md)）。
- `[P2]` 批量操作（分组改配置、分组排期）。

### 4.2 内容策略与选题（M-Strategy）
- `[P0]` 账号画像 / 策略配置：垂类、目标受众、内容形式（口播 / 二创 / 图文 / 数字人）、风格 tone、禁忌词、参考账号。
- `[P0]` 选题生成：基于画像 + 热点 + 历史表现，用 LLM 产出候选选题，运营可增删改。
- `[P1]` 选题库与去重：避免同账号 / 跨账号选题撞车。
- `[P1]` 热点 / 竞品输入：接入采集（MediaCrawler / B站数据）辅助选题。

### 4.3 素材采集（M-Source）
- `[P0]` 按选题 / 关键词检索素材（无版权素材库 Pexels/Pixabay、授权素材、自有素材库）。
- `[P0]` 素材入库：元数据（来源、授权、时长、标签）、去重。
- `[P1]` ⚠️ 版权 / 授权标记与校验：来源合法性、可用范围（强约束，见合规）。
- `[P2]` 采集 B站 / 全网公开热点素材供二创（须人工确认版权边界）。

### 4.4 素材加工与内容合成（M-Produce）
- `[P0]` 文案生成（LLM）：脚本 / 口播稿 / 标题 / 简介 / 标签，符合账号 tone 与平台规范。
- `[P0]` TTS 配音（edge-tts / CosyVoice 等），可按账号配置音色。
- `[P0]` 字幕生成（Whisper）与渲染。
- `[P0]` 视频合成：素材 + 配音 + 字幕 + 配乐 → 成片（参考 MoneyPrinterTurbo 流水线）。
- `[P1]` 数字人 / 口播视频（Heygem 等），用于资讯 / 知识垂类。
- `[P1]` 封面生成（模板 + AI 文字 / 图）。
- `[P1]` ⚠️ 原创度 / 查重：降低"低质重复"限流风险。
- `[P2]` 半自动剪辑工作台：人工微调入口。

### 4.5 审核与风控（M-Review）
- `[P0]` 自动预审：敏感词 / 违规内容 / 平台禁忌 / 标题党检测，给出风险分。
- `[P0]` 人工审核台：待发稿件列表、一键通过 / 退回 / 编辑。
- `[P1]` 风险分级路由：低风险自动发，中高风险转人工。
- `[P1]` ⚠️ 风控熔断：检测到账号限流 / 异常时，自动暂停该账号 / 该批次发布并告警。

### 4.6 投稿与排期（M-Publish）
- `[P0]` 投稿：封装 biliup，设置标题 / 简介 / 分区 tid / 标签 / 封面 → 提交。
- `[P0]` 排期：按账号规则（频率、时段）定时发布，支持随机抖动（拟人化）。
- `[P0]` 投稿结果回执：成功 / 失败 / 重试，失败原因记录。
- `[P1]` 发布节奏拟人化：随机时段、避免整点齐发、跨账号错峰。
- `[P2]` 一稿多账号 / 多平台分发（参考 SAU，注意原创度与差异化）。

### 4.7 数据回收与分析（M-Analytics）
- `[P0]` 拉取自家账号数据：播放、点赞、评论、涨粉、完播等。
- `[P1]` 内容 / 选题效果分析，反哺选题与策略。
- `[P1]` 账号成长趋势与异常检测。
- `[P2]` A/B 测试（标题 / 封面 / 时段）。

### 4.8 系统通用（M-System）
- `[P0]` 配置中心：账号 / 策略 / 规则均可配置，改配置不改代码。
- `[P0]` 任务调度与队列：可重试、可观测、限流。
- `[P0]` 日志与审计：谁在何时对哪个账号做了什么。
- `[P1]` 监控告警：账号异常、任务失败、登录态失效、风控事件 → 通知（飞书 / 邮件）。
- `[P1]` 权限与多人协作（角色权限）。

## 5. 关键用户故事

1. **作为运营负责人**，我想为某垂类新建一个账号画像并设定每周 3 更的策略，以便系统据此自动产出与排期。
2. **作为内容运营**，我想在审核台一次看到所有待发稿件的风险分，快速通过低风险、退回有问题的，以便高效把关。
3. **作为系统管理员**，我想在某账号被限流时收到告警并自动暂停其发布，以便止损并排查。
4. **作为运营**，我想系统对同一选题在不同账号生成差异化内容，以避免矩阵内容雷同被判重复。
5. **作为决策层**，我想看到 100 账号的健康度与风控事件总览，以评估规模与风险。

## 6. 验收标准（MVP，阶段一）

- [ ] 可配置 1～3 个账号的画像与策略，无需改代码。
- [ ] 给定选题，系统能自动完成：文案→配音→字幕→合成→预审→（人工通过后）投稿成功，全链路打通。
- [ ] 投稿成功率（技术层面，不含被平台拒）≥ 95%，失败有明确原因与重试。
- [ ] 自动预审能拦截预置的敏感词 / 违规样例（测试集召回率达标）。
- [ ] 能拉回已发内容的基础数据。
- [ ] 出现登录态失效 / 投稿失败 / 风控异常时有告警。
- [ ] 关键操作有日志审计。
- [ ] ⚠️ 通过一轮合规自查（见 [05](./05-合规与风险管理.md) 检查清单）。

## 7. 约束与假设

- ⚠️ **合规约束优先于功能**：任何功能不得以违反 B站规则 / 法律为代价实现（见 05）。
- 账号、手机号、实名、代理、指纹环境的合规获取由运营 / 行政侧负责，系统侧不生成虚假身份。
- LLM / TTS / 数字人能力可用 API 或本地模型，按成本与合规取舍。
- 一期以"质量优先、渐进放量"为原则，不追求一上来 100 个全开。
